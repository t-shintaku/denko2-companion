# 電工二種 合格伴走盤 (denko2-companion)

第二種電気工事士 **2026年度下期** に、電気知識ゼロから独学で合格し、**免状を受領する**までを伴走する
ローカルファーストPWA。

要件と実装状況の正本は、作者のローカルなノート(非公開)にある。
このリポジトリは実装のみ。学習データは端末の IndexedDB に入る。
既定では外部へ送信しない。**本人が設定でつないだときだけ**、本人の非公開リポジトリへ同期する。

## 動かす

```bash
npm install
npm run dev          # http://localhost:5173
npm run dev:lan      # スマホから同一LANで見るとき
npm test             # Vitest(128件)
npm run verify:pwa   # 実Chromiumで25項目(360x800/PWA/オフライン)
npm run build        # dist/ を生成(PWA の sw.js 込み)
npm run preview
```

Node 24 / npm 11 で確認。

## なぜ Google Drive の外にあるのか

Google Drive の同期フォルダ内に置くと **`npm install` が完走しない**。
実際に `EPERM: operation not permitted, rmdir` → `EBADF: bad file descriptor` で失敗した。
`node_modules` だけをジャンクションで逃がす手も試したが、
Google Drive のボリュームは NTFS ジャンクションを作れない(`Local NTFS volumes are required`)。

よって **Drive 外**に置いている。ノート側には要件と実装メモだけを残す。

**バックアップは Drive 任せにできない。** GitHub へ push するか、
学習データ自体は端末の IndexedDB にあり、アプリの「設定 → JSONへ書き出す」で
任意の場所へ保存できる(こちらが本命)。

## スマホで使うには配信先が要る(未決)

主端末はスマートフォンで、オフライン動作とホーム画面追加が要件にある。
PWA のインストールには **HTTPS 配信** が必要で、PC の dev サーバー(`http://192.168.x.x:5173`)では
Service Worker が登録されない。Sprint 1 の成果物は「ビルドすれば動く」ところまでで、
**配信先の決定は残タスク**。

配信先は **GitHub Pages**。`.github/workflows/deploy.yml` が main への push で
build → test → デプロイまで通す。`BASE_PATH` はリポジトリ名から自動で入る。

初回だけ手動:

```powershell
gh auth login                                   # 1回だけ
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1
```

- 公開URLは `https://<ユーザー名>.github.io/denko2-companion/`
- 学習データは端末内のみ。配信はアプリシェルの静的配信だけで、記録は外へ出ない
- **Git Bash から `BASE_PATH=/denko2-companion/ npm run build` してはいけない。**
  MSYS がパスを `/Program Files/Git/...` に書き換え、参照先の壊れた bundle ができる。
  PowerShell(`$env:BASE_PATH=...`)か CI を使う。実際にこれで一度壊れた。

## 端末間の同期

IndexedDB はブラウザ1つにつき1個の箱なので、つながないとスマホ・PC・タブレットが
別々の正答率とゲート判定を出す。設定 → 端末間の同期 でつなぐ。

- 同期先は**本人の非公開リポジトリ1つの中の `data/denko2.json`**。サーバーもアカウント追加も無い
- 認証は fine-grained PAT。必要な権限は対象リポジトリの **Contents: Read and write** だけ
- トークンは端末の IndexedDB(`syncMeta`)にだけ置く。**バックアップJSONにも同期ファイルにも入れない**
- 書き込みの4秒後・起動時・オンライン復帰時・画面復帰時に走る。オフラインの間は端末に貯める
- 同期のたびにコミットが積まれる = 履歴つきバックアップ。事故は過去コミットのJSONから戻せる

### 壊さないための規則(`domain/merge.ts`)

1. **削除を伝播しない。** 片方に無いことを「消された」と読まない。
   ある端末で全削除しても他端末の記録は死なない
2. **収束する。** 勝者は内容だけで決める。「ローカル優先」は端末ごとに別の勝者を出すので入れない
3. **進んだ事実は戻さない。** 完了した段階フラグは古い設定が来ても降りない
4. **壊れたリモートでローカルに触らない。** 検証を通らなければ読み書きどちらもしない

### 実接続で確認した挙動

作成直後のファイルは Contents API の GET が数秒 404 を返すことがある。
これを「リモートは空」と読んで sha 無しで書くと他端末の記録を踏み潰すが、
GitHub は sha 無しの上書きを 422 で拒む。**422 を競合として扱い読み直す**ことで守っている
(`tests/sync.test.ts` の反映遅れの回帰)。実接続の確認は:

```bash
DENKO2_LIVE_TOKEN=$(gh auth token) DENKO2_LIVE_REPO=owner/denko2-data \
  npx vitest run tests/github-live.test.ts
```

```
    backup.ts       JSONバックアップの検証と移行(FR-019)
    merge.ts        端末間同期の合体。削除しない・収束する・進んだ事実を戻さない
  sync/       同期。github.ts(API1枚)+ engine.ts(pull→合体→push)
  db/         Dexie(IndexedDB)。副作用はここだけ

  features/   画面
  state/      VaultContext(DB → 派生状態)
tests/        Vitest + React Testing Library
```

## 要件書との差分(意図的に変えたところ)

| 箇所 | 要件書 | 実装 | 理由 |
|---|---|---|---|
| 事務期限 | §10 は「7日以内の未完了事務期限」だけを見る | `opensAt`(受付開始)と期限超過を追加 | 申込開始 08-17 10:00 は締切(09-03)まで17日あり「7日以内」で拾えない。Sprint 1 の最優先目的が拾えなくなる |
| 日付型 | `applicationStart: string`(日付) | ISO8601+09:00(時刻つき) | 申込は 10:00 開始 / 17:00 締切。日付だけだと丸1日ずれる |
| カリキュラム | §7 に絶対日付 | JSONに日付を持たず、開始日と受験日から実行時に配置 | CBT日が実際の予約枠で動く。テストで日付の非混入を検証している |
| 20問診断 | §6 は「20問診断」をアプリ機能として書く | 外部(公式過去問)で解いて結果を登録する形 | 過去問の本文・図を収録しない(§4.3)。アプリ内出題は FR-010 の P1 |
| 日付ライブラリ | date-fns 等 | 依存を足さず `domain/jst.ts` に自作 | Drive外へ移す前提でも依存は少ないほうがよい。Intl だけで JST 固定は書ける |
| CSS | Tailwind または CSS Modules | 素の CSS + カスタムプロパティ | 依存とビルド設定を減らす。ダークモードは `prefers-color-scheme` |
| 技能ゲートの時間 | FR-011「直近3回中央値」/ FR-013「直近3回35分以内」 | 表示は中央値、ゲート判定は最大値(Sprint 3で実装) | 34/35/36分は中央値35で通ってしまうが、AT-006 は不通過を要求する。指標と判定条件を分ける |

## Codex独立レビューへの対応(2026-08-11)

Sprint 1 実装後、別のエージェント(Codex)が独立にレビューし、P0を4件指摘した。全件を修正し、
それぞれに回帰テストを置いた。指摘の妥当性はこちらでも一次資料に当たって確認している。

| 指摘 | 検証結果 | 対応 | テスト |
|---|---|---|---|
| CBT予約期限が「受験日の14日前」では公式締切より後になり得る | **正しい**。公式は年度固定の 9/9〜10/14 | `anchor` を fixed の公式値へ。逆算を廃止 | `adminTasks.test.ts`【回帰】 |
| 学習時間を実測せず見積を自動記録している | **正しい**。クリックだけで基礎180分が進んだ | 画面滞在を実測し、本人が確認・修正して記録。`estimatedMinutes` と分離 | `evidence.test.ts`【回帰】 |
| 基礎180分にオリエンテーション(見積100分)が算入される | **正しい**。実質80分で診断が開いた | `countsAsBasics()` を stage で判定。入口段階は算入しない | `evidence.test.ts`【回帰】 |
| 筆記方式でも学科日が固定されない | **正しい** | `paper` 選択で 2026-10-25 に固定し編集不可 | `app.test.tsx`【回帰】 |
| 空の日なら容量超過でも配置する例外 | **正しい**。平日35分に120分模試が載った | 例外を廃止。入る日が無ければ `oversizedLessonIds` として警告 | `schedule.test.ts`【回帰】 |
| `www01.shiken.or.jp` が旧ドメイン | **正しい**。証明書期限切れで到達不可を確認 | 現行URLへ差し替え、到達確認済みとして `fetched` | `curriculum-data.test.ts` |
| アプリを開かないと期限通知されない | 妥当 | 期限の `.ics` 出力を追加(7日前・前日のアラーム付き) | `ics.test.ts` |
| 技能日を自由選択できる | **正しい**。PDFに「試験地で設定日が違います」 | 「計画用の仮置き。受験票で確定」と明示 | `app.test.tsx` |

**このレビュー中に、レビューにも私にも見えていなかった誤りが1件出た。**
受験案内の本文を読んだところ、**受験手数料の入金期限は9月4日**で、申込締切(9月3日)とは別の日だった。
実装は9月3日17:00にしていたので、払える日を1日潰していた。独立した `payment` の公式期限として修正済み。

## 安全について

- 練習は試験用の非通電材料のみ。通電した自宅設備を練習対象にしない。
- 免状を受け取るまで直結式工事はできない。**免状前に照明が切れたら、待たずに電気工事店へ依頼する。**
- 合格 ≠ 完了。免状受領で最終到達。
